## VOX TYPE (голосовой ввод) — настроено 2026-11-04
Система: Arch + GNOME на Wayland, GTX 1650 (Vulkan). Сервис: `voxtype.service` (user, enabled).

Рабочая конфигурация `~/.config/voxtype/config.toml`:
- `model = "large-v3-turbo"` — скачана в `~/.local/share/voxtype/models/` (1.6 ГБ), грузится на GPU через Vulkan
- `language = ["ru", "en", "az"]` — автоопределение из трёх языков. Турецкий (tr) пробовали и убрали: whisper путал az↔tr. Азербайджанский всё равно остаётся слабым языком у whisper
- `flash_attention = true`
- `hotkey.key = "SCROLLLOCK"`, режим push-to-talk
- `mode = "paste"` — ОБЯЗАТЕЛЬНО для GNOME: текст идёт в буфер через `wl-copy`, затем Ctrl+V через `ydotool`
- `driver_order = ["ydotool", "clipboard"]`

ПОЧЕМУ ИМЕННО PASTE (не менять обратно на `type`):
- `wtype` на GNOME не работает — Mutter не поддерживает протокол `virtual-keyboard`
- `ydotool type` молча не печатает кириллицу (возвращает код 0, но текст не появляется)
- `paste` обходит оба ограничения

Пакеты: `ydotool` (+ `ydotool.service` user, демон ydotoold), `wl-clipboard`, `wtype`, `evtest`.

VAD включён (`[vad] enabled = true`, backend whisper, Silero `ggml-silero-vad.bin`). Проверено на тестах: на речи результат идентичен выключенному VAD, на 3 сек тишины без VAD whisper галлюцинировал "Thank you.", с VAD — "No speech detected". Выигрыш без потерь.

Чего НЕ делать: не ставить `initial_prompt` на азербайджанском — при `language = ["ru", "en", "az"]` подсказка на одном языке перетягивает автоопределение и портит русский/английский.
Для работы ydotool пользователь должен быть в группе `input` (он в ней).

Диагностика:
- `voxtype status` — idle/recording/transcribing
- `voxtype setup check` — проверка цепочки вывода
- `voxtype info accel` — работает ли GPU
- `journalctl --user -u voxtype.service` — если добавить `-v`, будет виден каждый шаг вывода
- временный подробный лог: drop-in `~/.config/systemd/user/voxtype.service.d/verbose.conf` с `ExecStart=/usr/bin/voxtype -v daemon`

OSD (индикатор записи) на GNOME НЕ работает — `voxtype-osd-gtk4` требует Layer Shell, которого в Mutter нет. Ошибки в логе нормальны, не чинить. О результате сообщают уведомления.

## TTS (озвучка текста) — настроено 2026-11-04
Пользователь читает текст из буфера обмена по горячей клавише.

Скрипт: `~/.local/bin/say-clipboard`
- берёт текст из буфера (`wl-paste`), прерывая предыдущее чтение (`pkill` piper/pw-play + `spd-say -C`)
- **кириллица → piper** (нейросеть, локально, быстро: 0.16 с на 3 с речи), модель `ru_RU-irina-medium.onnx`, воспроизведение через `pw-play`
- латиница → `spd-say -l en`, резерв `espeak-ng`
- если piper недоступен → резерв RHVoice через `spd-say -l ru`
- смена голоса: `SAY_VOICE=ru_RU-denis-medium` (мужской), модели в `~/.local/share/piper/voices/`
- скорость: `SAY_SPEED` (флаг piper `--length_scale`), сейчас **0.6** (≈ на 25% быстрее исходного). Меньше = быстрее. Замеры на одной фразе: 0.9→6.35 с, 0.8→5.97, 0.7→5.13, 0.65→5.11, 0.6→4.82, 0.5→4.32. Ниже 0.5 — тараторка
- английская ветка: piper `en_US-amy-medium` на **отдельной скорости `SAY_SPEED_EN`, решено 0.7** (пользователь выслушал 0.7/1.0/1.2 и выбрал 0.7; шкала piper: меньше=быстрое, 1.0=естественная)
- ограничение 2000 символов, пустой буфер → голосом «Буфер обмена пуст»

piper установлен БЕЗ пакета: `piper-tts` из AUR не собирается (yay подхватывает pyenv Python 3.10 без scikit-build), `piper-tts-bin` не проходит контрольную сумму. Вместо этого скачан официальный бинарник piper 1.2.0 с GitHub в `~/.local/opt/piper/`, симлинк `~/.local/bin/piper`. Модели с huggingface rhasspy/piper-voices (irina + denis, по 61 МБ).
ВНИМАНИЕ: `piper` в extra — это конфигуратор игровых мышей, НЕ TTS.

Хоткей: **Pause** (одна клавиша, верхний ряд рядом со ScrollLock), GNOME custom keybinding `custom7` в
`org.gnome.settings-daemon.plugins.media-keys.custom-keybindings`.
Остальные биндинги пользователя (Super+t/r/w/g/q/d, Ctrl+Alt+n) не трогать.

Важно: `spd-say` НЕ читает stdin без `-e`. Текст передавать аргументом: `spd-say -l ru -- "текст"`.
Установлено: `rhvoice`, `rhvoice-language-russian`, `rhvoice-voice-aleksandr-hq`, `speech-dispatcher`, `espeak-ng`, `festival`.
Альтернативы лучше по качеству: `piper` (extra, офлайн, нужна модель), `edge-tts` (AUR, нужен интернет).

## ВАРИАНТ-1 ЗАПУЩЕН: одна «студия» Silero на всё чтение — 2026-11-05
Причина доработки: в первой версии проектора каждый русский кусок =
отдельный запуск torch (старт ~2.4 с), а в живом тексте куски по 1 слову
→ дыры 2-4 с между словами. Прямой вопрос пользователя «не может ли Ами
читать русский» — нет, piper одноязычный, Amy=en-only.
РЕШЕНИЕ: silero-generate теперь ПАКЕТНЫЙ: stdin с кусками через \x1e +
--out ШАБЛОН с "##" (нумерация 01..); ОДНИМ процессом пишет все русские
куски подряд, каждый wav — атомарно (write .part → rename; ffmpeg atempo
во второй tmp-файл ".atempo.part", вход/выход разведены). soundfile
требует format="WAV" для .part-имён.
say-clipboard (смешанная ветка): batch silero в фоне (BATCH_PID) пишет
say-clipboard-rNN.wav по мере готовности; bash-цикл, играя rNN, ждёт
файл (поллинг 0.2 с, предел 30 с). batch умер → одиночный silero →
piper Ирина → RHVoice. Английские куски — piper Amy на лету (старт ~0.2 с
не даёт дыр). Теперь паузы между кусками = только смена диктора.
Чисто-русский текст пока: отдельный запуск silero на весь текст (это ок).
КРАЙН: play_en_chunk fallback строка: spd-say/espeak без stdin,
текст аргументом (xargs -0 -I{}), помнии потерян.
