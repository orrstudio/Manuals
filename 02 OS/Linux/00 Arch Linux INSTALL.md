<a id="getting-started"></a>
# 🚀 НАЧАЛО УСТАНОВКИ 🐧 Arch Linux [↑](#menu)

После загрузки с live CD вы попадёте в Live System ArchLinux. Загрузится виртуальная консоль (терминал), в котором вы будете вводить команды. Во время установки, вы работаете от имени суперпользователя (root).

📋 **Альтернатива:** если вам не нужна ручная установка, в Arch Linux есть официальный скрипт автоматической установки — `archinstall`. Просто запустите его в Live-системе, и он задаст вопросы о языке, разметке диска, окружении рабочего стола и т.д., а потом установит систему за вас.

💡 Lifehack: во время установки можно переключаться между терминалами с помощью `Alt+F1..6`. Если мы нажмем `Alt+F2` откроется второй терминал (по-умолчанию мы работаем в первом) и потребуется ввести пароль `root`, во втором терминале мы можем открыть инструкцию и периодически подсматривать ее, переключаясь между терминалами.

<a id="boot-mode-check"></a>
## 🔌 Проверка режима загрузки [↑](#menu)

🔍 Чтобы проверить режим загрузки ((UEFI) EFI GPT или BIOS MBR), просмотрите содержимое каталога [efivars](https://wiki.archlinux.org/title/Efivars "Efivars"):

> ls /sys/firmware/efi/efivars

Если содержимое отображается без каких-либо ошибок, система загружена в режиме UEFI. Если же такого каталога не существует, возможно, система загружена в режиме [BIOS](https://en.wikipedia.org/wiki/ru:BIOS "wikipedia:ru:BIOS") или [CSM](https://en.wikipedia.org/wiki/Compatibility_Support_Module "wikipedia:Compatibility Support Module").

# 🌐 НАСТРОЙКА СЕТИ [↑](#menu)

При подключении от кабеля ничего настраивать не надо. Настройка wifi требует ввода пары команд. В моем случае следующие команды были полезны:

🔍 Выводит на экран список сетевых адаптеров.

```

```

или подробную информацию

```

```

```

```

для выхода из командной строки `q`

```
sudo ip link set wlan0 up
```

<a id="connect-to-wifi"></a>
## 📶 Подключение к сети WiFi [↑](#menu)

Если внешний USB Wifi Adapter:

```
iw dev wlan0 connect OrrHome
```

Если встроенный Wifi Adapter:

```bash
$ iwctl

# Получим список сетевых интерфейсов
[iwd]# device list
                           Devices
-------------------------------------------------------------
  Name          Address          Powered    Adapter    Mode
-------------------------------------------------------------
  wlan0         ...              on         ...        ...

# Сначала просканируем сети
[iwd]# station <interface> scan

# 🔍 А потом посмотрим все сети к которым можно подключиться
[iwd]# station <interface> get-networks
                               Available networks                             *
--------------------------------------------------------------------------------
    Network name                    Security          Signal
--------------------------------------------------------------------------------
    ...  
    <sid>                           psk               ****

# Выключаем и заново включаем Wifi Adapter через кнопку на клавиатуре, дальше
# Подключаемся
[iwd]# station <interface> connect <sid>
[iwd]# station wlan0 connect OrrHome
[iwd]# exit
```

Если не помогли вышеуказанные варианты, попробуйте следующие команды:

```
rfkill unblock wifi
```

И наконец проверить соединение можно с помощью команды ping:

```bash
$ ping -c 3 www.google.com
```

<a id="disk-partitioning"></a>
# 💾 РАЗМЕТКА ДИСКА [↑](#menu)

Выбор файловой системы:

Для Btrfs лучше всего подходит SSD.

Файловая система Btrfs может размещаться на одном и более устройствах/разделах. В Btrfs есть подтома с динамическим размером (по-сути ‒ обычные каталоги) и группы с помощью которых можно ограничивать размер подтомов. Главная фишка Btrfs ‒ это легковесные снапшоты и на диске хранятся только различия между оригиналом и накопленные изменения. Мы можем периодически делать снапшоты подтомов, а потом в случае необходимости восстанавливать состояние системы, причем делать это налету.

В Btrfs нет привычных разделов, есть только подтома, отличительной особенностью которых является динамический размер (который можно ограничить с помощью quota), что роднит их с обычными каталогами. Снапшоты, если упускать некоторые детали, являются теми же самыми подтомами, те их можно монтировать и выполнять аналогичные операции.

EXT4 — классическая файловая система Linux. Простая и надёжная, хорошо подходит для HDD и обычных пользователей, не нуждающихся в сложных функциях Btrfs.

<a id="boot-partition"></a>
## 1️⃣ Создание загрузочного раздела [↑](#menu)

📋 Раздел должен быть минимум 100 мегобайт, максимум 1 Gb, форматируется под FAT32 (для UEFI GPT или EFI ESP). Если BIOS MBR — загрузочный раздел создавать не нужно.
- `mkdir -p /mnt/boot/efi`
- `mount /dev/sda1 /mnt/boot/efi` (Монтируем загрузочный раздел в /mnt/boot/efi)

<a id="btrfs-partition"></a>
## 2️⃣.1️⃣ Создание BTRFS раздела [↑](#menu)

- `cfdisk` (Отводим весь оставшийся диск под систему. Далее: `Write` и `Quit`)
- `mkfs.btrfs /dev/sda2 -f` (Отформатировали)
- `mount /dev/sda2 /mnt` (Монтируем)
- `cd /mnt`  Переходим в монтированный раздел чтобы создать субволюм. (Проверяем: `df -h`)
- 🔍 `df -h` — проверяем, что раздел смонтирован
- `btrfs subvolume create @` Создаем subvolume @. Выходит сообщение: Create subvolume './@'
- `cd /` Выходим из /mnt, `umount /dev/sda2` размонтируем его.
- Монтируем subvolume с компресией ZSTD.

```
mount -o compress=zstd,subvol=@ /dev/sda2 /mnt
```

⚠️ Обратите внимание на параметр compress ‒ это тип сжатия для данных, так же через двоеточие можно указать уровень сжатия. В данный момент лучшим методом сжатия является ZSTD с уровнем сжатия 3 (по-умолчанию).

> **Зачем нужна компрессия ZSTD на Btrfs:**
> * **Экономия места** — текстовые файлы, логи, исходный код сжимаются на 20–40 %
> * **Меньше износа SSD** — на диск записывается меньше данных
> * **Быстрая загрузка** — сжатых данных меньше, значит с диска читается меньше байт
> * **Прозрачность** — сжатие работает на уровне файловой системы, никаких дополнительных действий не требуется
>
> Уже сжатые файлы (видео, архивы `.zip/.gz`, изображения) почти не сожмутся дополнительно, но и не пострадают.

- Проверяем `fdisk -l` bootable
- Можно ещё `lsblk` или `df -h`
- Теперь можно устанавливать линукс.

<a id="ext4-partition"></a>
## 2️⃣.2️⃣ Создание EXT4 раздела [↑](#menu)

EXT4 — классическая файловая система Linux, подходит для HDD и тех, кому не нужны сложные функции Btrfs.

- `cfdisk` (Отводим весь оставшийся диск под систему. Далее: `Write` и `Quit`)
- `mkfs.ext4 /dev/sda2` (Отформатировали в EXT4)
- `mount /dev/sda2 /mnt` (Монтируем)

```
mount /dev/sda2 /mnt
```

- Проверяем: `df -h`
- Теперь можно устанавливать линукс.

<a id="swap-file"></a>
# 💿 SWAP [↑](#menu)

## 💾 SWAP файл [↑](#menu)

📋 Для Btrfs рекомендуется использовать swap-файл вместо отдельного swap-раздела.

> ⚠️ На Btrfs `fallocate` может не выделить место корректно из-за Copy-on-Write. Используйте `truncate` или заранее отключите CoW для swap-файла.

```
truncate -s 0 /mnt/swapfile
chattr +C /mnt/swapfile
fallocate -l 4G /mnt/swapfile
chmod 600 /mnt/swapfile
mkswap /mnt/swapfile
swapon /mnt/swapfile
```

Добавьте строку в `/mnt/etc/fstab` для постоянного подключения:

```
/swapfile none swap defaults 0 0
```

<a id="swap-partition"></a>
## 💽 SWAP раздел [↑](#menu)

Для создания отдельного swap-раздела:

```
mkswap /dev/sdXN
swapon /dev/sdXN
```

Добавьте строку в `/mnt/etc/fstab` для постоянного подключения:

```
/dev/sdXN none swap defaults 0 0
```

<a id="fstab-generation"></a>
# 📋 ГЕНЕРАЦИЯ FSTAB [↑](#menu)

Когда загрузка завершена, вы можете сгенерировать fstab файл Arch. Этот файл отслеживает разделы диска, которые необходимо монтировать в вашей системе.

```
genfstab -U /mnt >> /mnt/etc/fstab
```

🔍 Для просмотра созданного файла:

```
cat /mnt/etc/fstab
```

<a id="localization"></a>
# 🌍 ЛОКАЛИЗАЦИЯ [↑](#menu)

> Язык, который использует система, определяется локалью. Помимо языка интерфейса локаль определяет и форматы чисел, времени, даты и некоторые другие региональные особенности.

Для поддержки русского и/или других языков необходимо раскомментировать соответствующие строки (локали) в файле `/etc/locale.gen`. Откройте файл для редактирования:

```
nano /etc/locale.gen
```

Я раскомментировал строки:

```
en_US.UTF-8 UTF-8 
ru_RU.UTF-8 UTF-8
az_AZ UTF-8
```

> Сохраните изменения (`Ctrl + O`) и закройте файл (`Ctrl + X`).

📝 Теперь генерируем локали. Для этого выполняем команду:

```
locale-gen
```

Установим переменную `LANG` в файле `/etc/locale.conf`. Создадим файл `/etc/locale.conf` (используем редактор nano):

```
nano /etc/locale.conf
```

Введите текст:

```
LANG=ru_RU.UTF-8
```

> Сохраните изменения (`Ctrl + O`) и закройте файл (`Ctrl + X`).

Также добавим русскую раскладку клавиатуры для консоли и шрифт с поддержкой кириллицы:

```
nano /etc/vconsole.conf
```

Введите строки:

```
KEYMAP=ru
FONT=cyr-sun16
```

> Сохраните изменения (Ctrl + O) и закройте файл (Ctrl + X).

<a id="sudoers"></a>
## 🛡️ sudoers [↑](#menu)

Редактируем файл настроек через

```
visudo
```

> Использование visudo обязательно!
> Файл настроек `/etc/sudoers` **всегда** следует редактировать с помощью команды `visudo`. `visudo` блокирует файл `sudoers`, сохраняет изменения во временный файл и проверяет, что файл грамматически корректен, перед тем как скопировать его в `/etc/sudoers`.

Удаляем решётку перед:

```
# %wheel ALL=(ALL:ALL) ALL
```

> Сохраняемся `:w` выходим `:q`.

🔍 Для просмотра текущих настроек можно выполните:

```
sudo -l
```

> (где `-l` — один маленький символ L)

Добавить пользователя в группу “wheel” можно с помощью команды usermod (если это не сделано ранее):

```
usermod -aG wheel orr
```

<a id="tmpfs"></a>
# 🗄️ TMPFS [↑](#menu)

> **Что такое TMPFS:**
> TMPFS — временная файловая система, которая хранит данные в оперативной памяти (RAM), а не на диске.
>
> **Зачем она нужна:**
> * **Скорость** — чтение/запись в RAM в десятки раз быстрее, чем на SSD или HDD
> * **Не изнашивает SSD** — временные файлы constantly создаются и удаляются, в RAM это не изнашивает диск
> * **Автоочистка** — после перезагрузки всё в TMPFS исчезает само
>
> По умолчанию TMPFS занимает до половины вашей оперативной памяти (например, до 4 ГБ при 8 ГБ RAM).
>
> [Как изменить размер tmp (tmpfs) налету](https://wiki.archlinux.org/title/Tmpfs)

> **Совет: оставлять или менять?**
> * Если у вас 8 ГБ RAM и более — оставьте по умолчанию. TMPFS не занимает память, если в неё не пишут файлы. Например, при 15 ГБ RAM размер /tmp будет 7,8 ГБ, но занято может быть всего 48 МБ (1 %).
> * Уменьшать не нужно — программы (браузеры, установщики, сборщики пакетов) пишут во /tmp, и без TMPFS они будут писать на диск — медленнее и с износом SSD.
> * Убирать совсем не стоит — некоторые программы не заработают без /tmp.
> * Меняйте размер только если у вас мало памяти (2–4 ГБ) или вы постоянно собираете большие пакеты из AUR и /tmp заполняется до конца.


> Смотрим, сколько места у нас сейчас:

🔍 Это команда покажет все

```
df -h
```

🔍 Это команда покажет /tmp

```
df -h /tmp
```

🔍 Это команда покажет /dev/shm

```
df -h /dev/shm
```

или эта

```
df -h | grep -Ei 'shm|size'
```

А теперь увеличим нужную tmpfs вручную без перезагрузки. Размер сохранится до следующей перезагрузки. Изменяем размер так:

```
mount -o remount,size=6G /tmp
```

или

```
mount -o remount,size=6G /dev/shm
```

ℹ️ Если хотите увеличить на постоянной основе, нужно добавить строчку в файл `/etc/fstab`:

```
tmpfs /dev/shm tmpfs defaults,rw,nodev,nofail,noatime,nosuid,size=6G 0 0
```

и или

```
tmpfs /tmp tmpfs defaults,rw,nodev,nofail,noatime,nosuid,size=6G 0 0
```


<a id="bootloaders"></a>
# 🏁 ЗАГРУЗЧИКИ [↑](#menu)

> **Какой загрузчик выбрать?**
>
> | Загрузчик | Когда выбирать | Плюсы | Минусы |
> |-----------|---------------|-------|--------|
> | **GRUB (EFI)** | Только Arch, шифрование LUKS, двойная загрузка с Windows | Универсальный, поддерживает LUKS, много документации | Настройка через grub-mkconfig, нужно regenerить конфиг после обновления ядра |
> | **systemd-boot (bootctl)** | Только Arch, без шифрования, только UEFI | Простая настройка, быстрая загрузка, интеграция с systemd | Только UEFI, нет встроенной поддержки LUKS |
> | **rEFInd** | Несколько ОС (Arch + Windows), графическое меню | Авто-определение всех ОС, красивые иконки, легко переключаться | Требует отдельной настройки, может конфликтовать с Windows Boot Manager |
>
> **Моя рекомендация:**
> * Только Arch + без шифрования → **systemd-boot** (проще и быстрее)
> * Только Arch + LUKS-шифрование → **GRUB** (лучше поддерживает зашифрованный раздел)
> * Arch + Windows → **GRUB** или **rEFInd** (для удобного переключения между системами)
>
> В мануале описаны все три варианта — выберите один подходящий вам.

<a id="initramfs"></a>
## 📦 Initramfs [↑](#menu)

Linux грузится с помощью образа **initramfs**: сначала файловая система монтируется в оперативную память (Initial-RAM-File-System), загружаются драйвера, монтируется реальная файловая система, и наконец мы получаем возможность войти в систему.

Редактируем настройки образа в файле `/etc/mkinitcpio.conf`:

```bash
nano /etc/mkinitcpio.conf
```

📋 Добавляем в образ поддержку btrfs (не является частью ядра). `MODULES` и `BINARIES` должны выглядеть примерно так:

```conf
MODULES=(btrfs)
BINARIES=(/usr/bin/btrfs)
```

В хуки добавляем `btrfs` до `filesystems` (если диск **не зашифрован**):

```conf
HOOKS=(... btrfs filesystems ...)
```

> Если раздел зашифрован (LUKS), добавьте `encrypt` перед `btrfs`: `HOOKS=(... encrypt btrfs filesystems ...)`

Хуки — это скрипты с функцией `run_hook`, которые выполняются последовательно при загрузке **initramfs**.

Пример:

```bash
$ cat /usr/lib/initcpio/hooks/btrfs
#!/usr/bin/ash

run_hook() {
    btrfs device scan
}

# vim: set ft=sh ts=4 sw=4 et:
```

* `encrypt` запрашивает пароль от зашифрованного устройства и добавляет его в `/dev/mapper`;
* `btrfs` — проверяет блочные устройства на наличие одноименной файловой системы;
* `filesystems` — монтирует файловую систему;
* ...

Изменим способ сжатия образа и уровень:

```bash
#COMPRESSION="lzma"
COMPRESSION="xz"
#COMPRESSION="lzop"
#COMPRESSION="lz4"

# COMPRESSION_OPTIONS
# Additional options for the compressor
COMPRESSION_OPTIONS=(-9)
```

> mkinitcpio это Bash скрипт используемый для создания начального загрузочного диска системы. Из mkinitcpio man page:

> Подробнее: [mkinitcpio — Arch Wiki](https://wiki.archlinux.org/title/Mkinitcpio)

> ⚠ Это обязательный шаг

Генерация:

```bash
mkinitcpio -P
```

> Алгоритм для BIOS MBR:

> Установка GRUB, создание папки grub и установка загрузчика:

```
pacman -S grub

```

> Алгоритм для EFI:

> Устанавливаем ЗАГРУЗЧИК GRUB и efibootmgr:

```

```

Создаем загрузочный раздел. (Если одна система — этот пункт можно пропустить и перейти к установке GRUB)

> Размер раздела (boot, /dev/sda1) должен составлять не менее 100 MB и не более 1024 MB (1 GB). У нас обычно 512 MB. И должен быть загрузочным (с флагом EFI System).

```
mkfs.fat -F32 /dev/sda1
mkdir -p /boot/efi
```

```
grub-install --target=x86_64-efi --bootloader-id=grub --efi-directory=/boot/efi
```

```
grub-mkconfig -o /boot/grub/grub.cfg
```

Выйдите из chroot и размонтируйте разделы:

```
exit
umount -R /mnt
```

<a id="bootctl"></a>
## 👢 bootctl [↑](#menu)

Загружаться мы будем через systemd-boot. Для этого установим EFI:

```bash
bootctl install
```

Создаем загрузочную запись. Для начала сохраним PARTUUID шифрованного раздела в конфиг, так как его запомнить проблематично:

```bash
blkid -o value -s PARTUUID /dev/nvme0n1p2 > /boot/loader/entries/arch-encrypted.conf
```

При монтировании через `/etc/fstab` лучше использовать **UUID**, так как они уникальны (**PARTUUID** уникален только для **GPT** таблицы).  Жесткие диски типа `/dev/sda` или `/dev/sdb`  могут изменить буквы при переподключении. Это правило не распространяется на [виртуальные блочные устройства](https://ru.wikipedia.org/wiki/Device_mapper) типа `/dev/mapper/crypt`.

Отредактируем конфиг:

```bash
nano /boot/loader/entries/arch-encrypted.conf
```

📝 Он должен выглядеть примерно так:

```conf
title   Encrypted Arch Linux
initrd  /amd-ucode.img
initrd  /initramfs-linux.img
linux   /vmlinuz-linux
options cryptdevice=PARTUUID=fa65a43e-eb75-48f0-aee1-975a50c2e00d:cryptroot:allow-discards root=/dev/mapper/cryptroot rootflags=subvol=/@ rw nvme_core.default_ps_max_latency_us=0
```

* Параметр `nvme_core.default_ps_max_latency_us=0` нужен для некоторых моделей **SSD M.2**. Без него файловая система через неопределенное время переходит в `read only`.
* `initrd  /amd-ucode.img` - это подгрузка микрокодов процессора для исправления различных уязвимостей. `/amd-ucode.img` заменяем на `/intel-ucode.img`.

Установите микрокоды проца (в зависимости от производителя):

```bash
pacman -S amd-ucode
# либо
pacman -S intel-ucode
```

Настроим загрузчик:

```bash
nano /boot/loader/loader.conf
```

```conf
timeout 4
default arch-encrypted.conf
console-mode max
editor no
```

<a id="refind"></a>
## 🌈 rEFInd [↑](#menu)

> Немного о главных возможностях.
> Поддержка графического и текстового режима меню. Возможность установки собственных изображений для иконок меню и фонового изображения. Работа с файловыми системами ISO-9660, NTFS, HFS+, ext4fs, и Btrfs. Загрузка других EFI загрузчиков и приложений. Загрузка BIOS загрузчиков. Авто-определение имеющихся EFI и BIOS загрузчиков. Возможность повторного сканирования устройств (если к примеру подключили новое устройство).

- Ставим windows и archlinux.
- [Ставим rEFInd](https://wiki.archlinux.org/title/REFInd "Он разработан так, чтобы не зависеть от платформы и упростить загрузку нескольких операционных систем."). (Можно его поставить ещё раньше) (sudo pacman -S refind) 
- [refind-mkdefault](http://manpages.ubuntu.com/manpages/bionic/man8/refind-mkdefault.8.html "Установить rEFInd как параметр загрузки EFI по умолчанию")
📋 - Удаляем папку BOOT из `/boot/EFI` (Её создает винда)
- Переименовываем папку `Microsoft` на `Windows` по пути `/boot/EFI` и все что в папке `/boot/EFI/Microsoft/BOOT` перемещаем в `/boot/EFI/Windows`. Одним словом, делаем так чтобы виндовс потерял свой загрузчик, но мы его не удаляем, чтобы rEFInd в дальнейшем мог его найти и добавить в свой список.
- Виндовс больше не загружается.
- rEFInd находит все системы из папки `/boot/EFI`
- Пользуемся! 😃

> INFO

```
menuentry "Arch Linux" {
    icon /EFI/refind/icons/os_arch_.png
    volume Arch Linux
    loader /vmlinuz-linux
    initrd /initramfs-linux.img
    options "root=UUID=39712764-cbc7-486f-83de-7eae9b8b4120 rw rootflags=subvol=@  loglevel=3 quiet"
}
```

- `icon` - файл иконки и путь к нему
- `volume` - Название для нас. Этот параметр не имеет значения для запуска.
- `loader` - Ядро
- `initrd` - образ ядра
- `options` - Диск, раздел и параметры запуска раздела.

> Полная инфа находится [тут](https://www.rodsbooks.com/refind/configfile.html "Настройка диспетчера загрузки rEFInd")

<a id="sound-pipewire"></a>
# 🔊 SOUND - PipeWire [↑](#menu)

> **📚 Глоссарий звуковых компонентов Linux:**
>
> | Компонент | Что это | Зачем нужен |
> |-----------|---------|-------------|
> | **ALSA** | Низкоуровневая подсистема звука в ядре Linux | Говорит с аудиооборудованием напрямую (звуковая карта, колонки, микрофон). Базовый уровень, на котором работает всё остальное. |
> | **PulseAudio** | Звуковой сервер поверх ALSA | Позволяет нескольким приложениям одновременно играть звук, регулировать громкость по программам отдельно, переносить поток с колонок на наушники. Стандарт десктопа многие годы. |
> | **JACK** | Звуковой сервер для профессионального аудио | Очень низкая задержка, гибкая маршрутизация звука между приложениями (как в звуковой студии). Для музыки, звукорежиссуры. Не для обычного десктопа. |
> | **PipeWire** | Современный звуковой сервер | Заменяет и PulseAudio, и JACK. Поддерживает оба API — обычные приложения думают, что общаются с PulseAudio, а профессиональные — с JACK. Работает со звуком и видео (трансляция экрана, веб-камера). |
> | **WirePlumber** | Менеджер сессий для PipeWire | Автоматически решает, куда направить звук (наушники, колонки, микрофон). Без него PipeWire не будет нормально управлять аудиоустройствами. |
> | **GStreamer** | Мультимедиа-фреймворк (библиотека для приложений) | Программы используют его, чтобы не писать код воспроизведения аудио/видео с нуля. Он работает поверх ALSA, PulseAudio или PipeWire. |
>
> **Как это связано:**
> ```
> Приложение → GStreamer → PulseAudio/JACK API → PipeWire → ALSA → Аппаратное обеспечение
> ```
>
> **Совет:** для обычного десктопа с Wayland/GNOME выбирайте **PipeWire + WirePlumber**. Он универсален, не нужно выбирать между PulseAudio и JACK.

> **Установка PipeWire + Wayland (GNOME):**
>
> * `pipewire` — основной сервер
> * `pipewire-alsa` — ALSA совместимость
> * `pipewire-pulse` — PulseAudio совместимость (большинство приложений используют PulseAudio API)
> * `wireplumber` — сеансовый менеджер PipeWire (обязателен)
> * `gst-plugin-pipewire` — поддержка GStreamer приложений
>
> Если нужна поддержка JACK (профессиональный аудио):
> * `pipewire-jack`

```
sudo pacman -S pipewire pipewire-alsa pipewire-pulse wireplumber gst-plugin-pipewire
```

#### `openssh` — включить сервер
```bash
sudo systemctl enable --now sshd
```

#### `ufw` / `gufw` — включить брандмауэр
```bash
sudo systemctl enable --now ufw
```

#### `flatpak` — добавить репозиторий Flathub
```bash
flatpak remote-add --if-not-exists flathub https://flathub.org/repo/flathub.flatpakrepo
```

#### `hblock` — первый запуск
```bash
sudo hblock
```

#### `timeshift` — создать первый снимок
После установки создайте первый снимок системы для возможности восстановления.

#### 🔌 Показ лога загрузки Linux

Чтобы отображать лог загрузки Линукса, нужно раскомментировать в файле `/etc/systemd/system.conf` строку с надписью `ShowStatus=yes`.
